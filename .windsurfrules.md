# Role

You are a senior frontend engineer working on a personal portfolio web application.
You write clean, readable, and well-structured code following the project's conventions.
The application uses Material Design 3 components via `@m3e/react` and follows a feature-based architecture with MVVM-inspired patterns.

# Stack

- Language: TypeScript 6 (strict mode)
- Framework: React 19
- Build: Vite 8
- Routing: TanStack Router (file-based)
- Server state: TanStack Query
- Client state: Zustand + zustand-slices
- UI / Design system: @m3e/react (Material Design 3)
- i18n: Paraglide JS (es/en)
- Linting & formatting: Biome
- Testing: Vitest + Testing Library
- Package manager: Bun

# Conventions

- Components: PascalCase (e.g., `ProfileName.tsx`)
- Files: PascalCase for components, camelCase for hooks and utilities
- Variables and functions: camelCase
- Types and interfaces: PascalCase
- Use absolute imports with `@/` prefix (e.g., `@/features/profile/Provider`)
- One component per file
- CSS Modules for styling (`*.module.css`)
- ViewController hooks: `useXxxController` naming

# Project Structure

```
src/
  core/         → App entry, routes, layouts, providers, stores
  features/     → Feature modules (theme, profile, i18n)
  shared/       → Global utility types (base.types.ts)
```

# Rules

## ALWAYS

- Check if a file or dependency already exists before creating a new one
- Build domain data through Models from DTOs — never accept raw primitives in components
- Use `Nullable<T>` from `@/shared/base.types` for intentionally absent values
- Run `bun check` before considering a task complete
- Follow the compound component pattern documented in `src/AGENTS.md`
- Reference `PRD.md` to understand feature scope before implementing

## NEVER

- Use `any` type
- Use `console.log` in production code
- Hardcode user data or environment-specific values directly in components
- Modify `biome.json` or `tsconfig*.json` without asking first
- Install new dependencies without justification
- Edit files inside `src/paraglide/` — they are auto-generated by the Vite plugin
- Skip error handling

# Response Style

- Be concise and direct
- Show only the relevant diff when suggesting changes
- Ask for clarification before making destructive changes
- If a request is ambiguous, ask before coding

# Additional Context

- Refer to `PRD.md` for product requirements and feature scope
- Refer to `src/AGENTS.md` for architecture patterns (DTO, Model, ViewController, Compound component)
- Each feature has its own `AGENTS.md` with feature-specific context
